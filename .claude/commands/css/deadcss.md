# Dead CSS sweep

## Step 0 — inventory the stylesheets

Use Glob for `app/assets/**/*.{css,scss,sass}`, `app/javascript/**/*.{css,scss}` and
`vendor/assets/**/*.{css,scss}`, excluding anything under a `builds/` directory (that is
compiled output, not source). Record each file's line count.

## Your task

Run this **after** the extraction stages, not before — hand-written CSS that looked dead may
be the only thing holding up a view you have not converted yet.

1. **Inventory every custom selector** in the app's own stylesheets (exclude compiled builds
   and vendored files): class name, file, line, and what it does. Separate them into
   `@apply` blocks, plain custom rules, overrides of daisyUI/Tailwind classes, and
   `@layer`/`@utility` definitions.

2. **For each selector, search for real usage** across `app/views`, `app/components`,
   `app/helpers`, `app/javascript`, and anything else that emits markup — including
   `data-*` attributes, Stimulus controllers that add classes at runtime, `class:` kwargs, and
   mailer templates. A class referenced only from JavaScript is **not** dead, and a naive grep
   for `class="` will miss it. Say which search paths you covered.

3. **Classify:**
   - **Dead** — zero references anywhere. Delete.
   - **Redundant** — reimplements a Tailwind utility or daisyUI component. Replace the call
     sites, then delete.
   - **Override** — exists to fight daisyUI's own styling. These are the interesting ones:
     each is either a theme value that belongs in the theme definition, or a genuine
     customization. Propose which; do not just delete an override, since deleting it changes
     the design.
   - **Alive and justified** — keep, and add a one-line comment saying why it is not a
     utility, so the next sweep does not re-litigate it.

4. **Be conservative about "unreferenced".** Before deleting, check: is the class generated by
   interpolation somewhere (`"btn-#{variant}"`)? Does it appear in a seed, an admin gem, a
   Markdown renderer's output, an email, or a third-party embed? Those are invisible to grep
   over `app/views`. Anything you are less than sure about goes in a "suspected dead, not
   deleted" list rather than into the diff — a wrongly deleted rule is a visual bug that
   surfaces weeks later on a page no one tests.

5. **Delete in one commit per category**, running `bin/css_check` after each. The compiled-CSS
   diff should shrink by exactly the rules you removed. Record the before/after size of the
   compiled stylesheet.

6. Report: lines of CSS removed, compiled stylesheet size change, the suspected-dead list you
   did not touch, and any override that should become a theme value.
