# Recurring UI markup in `app/views`

Inventory of markup patterns that recur across the 643 ERB templates,
sorted by number of grep-verified occurrences (counts and file:line lists
generated by ripgrep, 2026-07-30). "Occurrences" counts matched lines except
where a pattern is inherently file-scoped (stubs, page twins), where it
counts files.

Method: repeated-`class=""`-string extraction, verbatim-duplicated-line
extraction (all lines >45 chars appearing ≥4×), signature greps per
candidate, and a full pairwise diff of every same-basename template pair
(similarity = shared lines / total lines).

Excluded as working-as-intended: helper DSL calls that vary genuinely
(`hero_panel` titles, `ui_section`, `t.cell`), empty states (all via
`ui_empty_state`), spacing-only utility classes (`mb-2` ×89 etc.), and
`fa_icon` at large (raw `<i class="fa-solid">` appears only 2×; the helper
won). Raw `<table>` exists only in mail views; application tables all go
through `ui_table`.

## ui_table full_width+striped opener — 65 occurrences

**Variance:** Identical argument string; only the trailing options occasionally differ.

```erb
<%= ui_table full_width: true, striped: true do |t| %>
```

94 `ui_table` mentions in views; 65 open with this exact argument pair
(7 of them also adding `responsive: true`). Fewer than a third use anything else —
`full_width: true, striped: true` is the de-facto default and could be the
helper's actual default.

**Not taken (owner ruling, 2026-10-03):** `full_width:` stays `false` by default.
A fit-width box is capped at its parent, so it never pushes a page sideways;
a table that should span the page says `full_width: true` at its call site.

# Part 2 — Structural families (same shape, different parameters)

Text search finds verbatim repeats; this part finds blocks whose **element
structure, class strings, and helper calls are identical** while labels, URLs,
icons, and ivars differ. Method: every template line normalized to a
structural skeleton (class/data attributes kept verbatim; quoted strings →
`"S"`, `*_path`/`*_url` → `PATH`, `@ivar` → `@V`, numbers → `N`; pure prose
dropped), 4-line sliding-window hashing extended to maximal shared runs, plus
whole-file Jaccard clustering on normalized-line multisets. The values that
filled each slot were captured per occurrence — those are the parameter lists
below. Generic runs (paragraph chains, closing-tag stacks) were discarded.

Families **compose**: the page opener (family 2) is the head of the CRUD page
(1) and the report page (8); the form footer (5) recurs inside the modal
scaffold (3); families 6–7 are organs of 8. Part 1's flat line counts
(back-link slot ×149, GET filter opener ×17, `ui_table` opener ×65) are the
same duplication seen one line at a time.
